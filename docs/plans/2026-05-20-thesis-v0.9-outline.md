## v0.9 section map (proposed order)

### 0. Disclosure *(NEW — first thing after the dek)* → closes A1
- 3-4 sentences, plain: Josh owns agentsfirst.dev, operates the hosted scorer, publishes Agent Readiness Reports on named companies, and is CEO of Capital Factory (a VC firm) whose portfolio includes companies in the agent-tooling space.
- State the obvious incentive out loud: "I benefit if this framework is adopted. Read accordingly."
- Link to a full `/about/conflict-of-interest` page (must ship with v0.9).
- One line on what's *not* conflicted: the rubric + probe + scoring are open-source and reproducible — verify the scores yourself.
- **Why first:** the panel's #1 structural hit was that the conflict is real and hidden. Naming it up front converts the biggest credibility liability into a credibility signal.

### 1. Every product is getting a second customer *(KEEP, tighten ~20%)*
- The human who pays / the agent who decides. The tool-list framing. This is the strongest part of the thesis — leave the spine, cut the repetition.

### 2. The shift — with honest evidence *(REWRITE)* → closes A2
- Keep the Mobile First analogy but **fix the anchor**: 2009 Mobile First was anchored by open-web mobile traffic share; this is anchored by vendor telemetry. Say so.
- Reframe 58.9% as **one leading indicator at the LLM-traffic layer, vendor-sourced, not yet corroborated at the SaaS-workflow layer.** Move the caveat (currently buried in §"What we don't know") up next to the stat.
- Add ≥1 non-Vercel signal if one exists by publish time (independent telemetry, academic, or a second gateway). If none exists, say "we only have one data point and it's vendor-sourced" — explicitly. Honesty here is cheaper than the attack.
- Keep the AWS/Stripe/Cloudflare "agents have payment rails" production proof — that's the strongest non-stat evidence and it survived the review untouched.

### 3. The strategic case *(KEEP core, cut ~30%)*
- Discovery compression (days→seconds), connection-cost-≈0, agent ergonomics moat, network compatibility, metrics. All survived review.
- Trim the protocol-landscape + context-window subsections — they're true but they're the parts that read like a vendor explainer.

### 4. What's actually new (and what isn't) *(NEW — load-bearing)* → closes A3 + A5
- Concede hard, up front: "Most of what follows is established engineering. Two things are genuinely new."
- **Genuinely new (2):** Interface First (designing a tool interface for a consumer with zero prior context about your product) + Contract First (writing usage rules an LLM will actually follow). No clean pre-agent analog.
- **Applied, not new (the rest):** one table, one line each — Prep Gates = health checks; Typed State = schemas+migrations; Visible Outputs = observability into human tools; Multi-Model Verification = distributed-systems agreement; Perspective Dispatch = structured code review; Autonomous Recovery = SRE retry; Inspectable State = the agent-facing twin of Visible Outputs.
- The thesis: **"The novelty isn't the practices. It's knowing which ones become load-bearing when your operator can't improvise."** Defend that line — it's the actual contribution and it's defensible.

### 5. The implementation principles *(COMPRESS HARD)* → closes A3
- Was: 9 principles each with a paragraph + a "what's new vs applied" essay. Now: the §4 table already did the framing. Here, keep the one-paragraph treatment ONLY for the 2 novel principles. The 7 applied ones get one sentence + a link to a deep-dive page each.
- Net: this section roughly halves.

### 6. Security *(PROMOTE + EXPAND)* → closes A4
- Lead with the stakes: an agent with write access to production, driven by a model that has the lethal trifecta (private data + untrusted content + exfiltration channel) by construction.
- Keep the auth patterns (scoped tokens, OAuth+PKCE, short-lived, audit logging).
- **Add real prompt-injection treatment:** tool-description injection, confused-deputy via tool results, why "validate against known-good signatures" is necessary-not-sufficient. Cite the actual literature (Willison's lethal-trifecta framing — the persona who attacked us on exactly this).
- Add a "default-deny / human-in-loop for irreversible actions" line — squares with the Slow Chatbot anti-pattern without contradicting it (autonomy for reversible, gate for irreversible).

### 7. Levels of adoption *(KEEP, trim)*
- L0–L4 ladder. Keep. Trim the Cloudflare-ARS / a14y / Fivetran comparison prose to a single table row each — it's useful positioning but currently over-long.

### 8. The honest cost + What we don't know *(MERGE)*
- These two sections overlap. Merge into one "Costs & open questions." Keep the maturity/evidence comparison table (TDD/API First/Mobile First/Agents First) — it's the most intellectually honest artifact in the doc and the panel didn't touch it.

### 9. The bottom line *(KEEP, soften the manifesto)*
- Panel: "credibility gap between 'early/emerging evidence' and 'your next feature will be used by an agent before a human ever sees it.' Pick one tone." → keep the punch but qualify the absolute claim ("increasingly" / "for a growing share of workflows").

### 10. We ate our own dogfood *(KEEP — but reframe)*
- Panel called this "ironically the most damaging" because it shows even the author isn't fully on the principles. **Reframe as a feature, not a confession:** the rubric is honest enough to flunk its own author's site, and the score moved 25→80 because the rubric is actionable. That's evidence the scoring works, not evidence of hypocrisy.
