## Agents First Score — crunchbase.com

**Score: 37/100 · Level 2 (Agent-Aware) 🚧**

Crunchbase is the textbook fortress-data product: every agent-readiness signal exists technically — but every answer is "no, pay for the API." The consumer site (`www.crunchbase.com`) is blanket-blocked at Cloudflare for non-browser user-agents (HTTP 403) and bans 15+ named AI bots by name in `robots.txt`. The developer subdomain (`data.crunchbase.com`) is wildly different: it ships a real `/llms.txt`, supports Markdown content negotiation on every doc page, exposes OpenAPI specs through the API itself, and offers RFC 8414 OAuth discovery with PKCE. The agent-readable infrastructure is there. It's just gated behind a paid API and isn't discoverable from the main domain. Crunchbase scores Level 2 by the rubric, but the posture is "Agents-as-Adversary" — which is a defensible product decision and a missed agent-economy revenue opportunity.

### What's working

- ✅ **Content accessibility** (20/20) — `data.crunchbase.com` docs are all Markdown-content-negotiable (every page has a `.md` URL variant, indexed in `/llms.txt`). Sitemap is declared in `robots.txt`. Four OpenAPI specs are documented (`getopenapispecjson-*`). All three sub-items pass.
- ✅ **Agent capabilities — OAuth discovery** (5/5) — [`/.well-known/oauth-authorization-server`](https://www.crunchbase.com/.well-known/oauth-authorization-server) returns a valid RFC 8414 document with `code` response type, `authorization_code` + `refresh_token` grant types, and S256 PKCE. Modern and complete.
- ✅ **Discoverability — robots.txt is AI-aware** (5/5 for the form) — `robots.txt` has explicit per-bot User-agent stanzas for 15+ named AI agents (CCBot, ChatGPT-User, OAI-SearchBot, GPTBot, Google-Extended, anthropic-ai, Diffbot, Bytespider, cohere-ai, Claude-Web, PerplexityBot, FacebookBot, and more). They know agents exist.
- ✅ **Discoverability — llms.txt** (5/10 partial) — Real `/llms.txt` on `data.crunchbase.com` (auto-generated by Readme.com, 284 lines, well-formed). Half credit because it's on the developer subdomain, not the main `www` domain where an unmotivated agent would land first.

### What's missing

- ⚠️ **Bot access control** (2/15) — Named-bot stanzas exist but every directive is `Disallow: /`. Per-bot allow/deny posture is *shaped* correctly but uniformly negative. No [Cloudflare Content Signals](https://blog.cloudflare.com/content-signals-policy/) declarations, no business-tier "train=no, agent-with-token=yes" signal. Crunchbase is on Cloudflare's edge — they have the lever and aren't pulling it.
- ⚠️ **Agent capabilities — MCP Server Card** (0/15) — No first-party MCP server. No `/.well-known/mcp-server-card.json`. No `/.well-known/mcp-server-card`. Community MCP servers exist on [mcp.so](https://mcp.so/server/crunchbase/Cyreslab-AI), [Zapier MCP](https://zapier.com/mcp/crunchbase), and [mcpbundles](https://www.mcpbundles.com/providers/crunchbase) — but none are blessed by Crunchbase. The agent economy is being built on MCP; Crunchbase isn't in the lineup.
- ⚠️ **Agent capabilities — CLI / typed SDK** (0/10) — No first-party CLI. No published TypeScript / Python SDK with maintained typing. Integrators write their own HTTP clients.
- ⚠️ **Discoverability — AGENTS.md** (0/10) — No `/AGENTS.md` or `/.well-known/agent-rules` on either domain. Crunchbase has unique data-licensing terms (resale restrictions, citation requirements, derivative-work rules) that agents will quietly violate without an explicit contract artifact. AGENTS.md is the disclosure surface.
- ⚠️ **Visibility of agent integrations** (0/10) — Their docs don't acknowledge agent integration as a product category. No "install our MCP server" alongside "get an API key." The default agent-onboarding path is invisible.

### 🚨 Anti-patterns flagged

- **The Invisible Product** — Crunchbase has no first-party agent surface. Third parties have done the work (Zapier, mcp.so, mcpbundles, Cyreslab) but those integrations don't carry Crunchbase's quality / SLA / data-license guarantees. From the agent's perspective, "search for company X funding round" doesn't resolve to a verified Crunchbase tool by default.
- **Agents-as-Adversary** *(worth naming, not in the canonical list)* — Robots.txt explicitly denies 15+ named AI bots; Cloudflare 403s every non-browser User-Agent at the edge of the consumer domain. Every agent-readiness signal that exists (OAuth, llms.txt, OpenAPI) is gated behind a paid API tier and isn't surfaced from the consumer site. This is a logical product decision for a company whose moat *is* the data. It's also the posture most likely to be routed around — agents will reach for [PitchBook](/scores/pitchbook), public corporate registries, OpenCorporates, and SimilarWeb-equivalent alternatives before paying Crunchbase, because alternatives ship the agent surface and Crunchbase doesn't.

### 🎯 Top moves to climb a level

Order by leverage:

1. **Ship a first-party Crunchbase MCP server** (worth ~15 pts; biggest unlock by far). The community has already built three. Bless one (or build the official version), host it at `mcp.crunchbase.com`, sign the binary, gate access behind the same OAuth flow that already exists. Bill the same metered tier as the REST API. The agent economy is the next API funnel — Crunchbase being absent from MCP registries is leaving developer-led revenue on the table. Suggested path: take the [Cyreslab community server](https://mcp.so/server/crunchbase/Cyreslab-AI) (30 tools, already mapped to Crunchbase's API), audit it, version it, and ship `npx @crunchbase/mcp` with a license-key prompt on first run.
2. **Add `www.crunchbase.com/llms.txt` that points agents at the developer subdomain** (worth ~10 pts). One file. Three sentences. *"For API access and agent integrations, see [data.crunchbase.com](https://data.crunchbase.com). Authenticate via [/.well-known/oauth-authorization-server](/.well-known/oauth-authorization-server). License terms at /docs/terms."* That earns full Discoverability + signals "we know you're here, here's where to go" instead of "403, go away."
3. **Publish a hand-authored `AGENTS.md`** (worth ~10 pts). ~50 lines. The non-obvious rules — citation language, rate limits per tier, scope hierarchy (`lists.read` vs full read), license tier required for redistribution, attribution patterns for derived datasets. Crunchbase's data terms are uniquely consequential; agents *will* violate them without explicit guidance, and that exposes Crunchbase to enforcement work the contract artifact would prevent.
4. **Move bot policy from `Disallow: /` to Cloudflare Content Signals with three explicit lanes** (worth ~10 pts). `train=no`, `search=yes`, `agent-with-paid-token=yes`. This is the modern stance for paid-data companies — it differentiates "agents scraping for training data" (the threat) from "agents querying via paid API token" (the customer). Today's `robots.txt` blanket-bans both.
